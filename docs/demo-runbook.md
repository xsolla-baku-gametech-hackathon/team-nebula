# Demo runbook

Technical protocol for making the live path unable to fail. This is engineering, not stagecraft — every item here is a code path or a checked artifact.

---

## Failure ladder

Four levels. Each one is fully built and rehearsed before the one above it is trusted.

```
L0   Live app, live LLM + embedding calls
        ↓ any API slow or failing
L1   DEMO_MODE=true — all AI served from a fixture map, zero network
        ↓ app fails to boot, deploy broken
L2   Local build on a laptop, same DEMO_MODE
        ↓ laptop or display fails
L3   Recorded screen capture of the full flow
```

L1 is the level you actually present from. L0 is what you test with. Treating L1 as the default rather than the emergency removes an entire category of anxiety.

---

## DEMO_MODE

`DEMO_MODE=true` replaces both AI touchpoints with a fixture lookup keyed by input hash.

```ts
// lib/ai/client.ts
export async function extractConcept(input: ExtractInput) {
  if (process.env.DEMO_MODE === 'true') {
    const key = hashInput(input);
    const hit = DEMO_FIXTURES.concepts[key];
    if (hit) return hit;
    return DEMO_FIXTURES.concepts.default;   // never miss, never throw
  }
  return callLLM(input);
}
```

Same interception for embeddings. Fixtures live in `lib/demo/fixtures.ts`, generated by a script that runs the real path and records the results:

```bash
DEMO_CAPTURE=true pnpm demo:capture
```

The capture script runs the three demo scripts end to end against live APIs, serializes every request/response pair, and writes the fixture map. Regenerate it after any prompt change.

**Crucially, there is a `default` entry.** An unrecognized input returns a plausible generic concept rather than throwing. If someone in the audience asks you to type in their game idea, the demo does something reasonable instead of erroring.

`/api/health` reports `demoMode: true` so you can confirm which mode you are in without guessing.

## Demo scripts

Three prepared inputs, captured into fixtures, rehearsed.

**Script A — the main flow.** The co-op horror concept. Hits a dense, well-populated corpus region with recognizable comparables (Phasmophobia, Demonologist, DEVOUR) and a genuinely crowded forward calendar. This is what you present.

**Script B — the contrast.** A cozy management game. Different tag cluster, different saturation profile, calendar shows a quiet window. Demonstrates the tool responds to input rather than producing one canned answer. Useful if asked "does it always say move?"

**Script C — the audience input.** A short generic concept for when someone asks you to try theirs. Runs through the `default` fixture path if their exact text isn't captured.

All three are in `lib/demo/scripts.ts` with their exact input text, so rehearsals use byte-identical input every time.

## Pre-demo checklist

Run in order. Every item is verifiable, none is a judgement call.

```
□ pnpm build succeeds with zero warnings
□ /api/health returns ok, corpus loaded, expected count
□ /api/health reports demoMode: true
□ Script A: landing → forecast, no console errors, under 8 seconds
□ Script B: same
□ Script C: default fixture path returns without error
□ Reset button clears state and returns to landing in one click
□ PDF print preview: no clipped charts, no orphaned headings
□ JSON export downloads and re-imports successfully
□ Forward calendar has ≥ 3 competing releases in the highlighted week
□ Every visible number has a provenance tag
□ Browser zoom set for projector legibility, tested at that zoom
□ Recording (L3) exists and plays
□ Laptop on power, sleep disabled, notifications off
□ Second browser tab open on the finished forecast, as instant L0 backup
```

The last item is cheap insurance. If the live run stalls, you switch tabs to a completed analysis and keep talking. No apology needed, no dead air.

## Freeze protocol

Two stages, both hard.

**Feature freeze.** No new functionality after this point. Bug fixes and visual polish only. Anything not working now is cut, not rescued. The most common way a demo breaks is a feature added in the last hours that touched shared state.

**Hard freeze.** No commits to `main` at all after this point except for a demo-blocking bug, and those require someone else to confirm the bug exists before the fix is written. Between hard freeze and presenting, the deployed artifact does not change.

At hard freeze:

```bash
git tag demo-freeze
pnpm demo:capture              # regenerate fixtures against final prompts
pnpm build && pnpm start       # verify the production build, not dev
```

Record the L3 video against the frozen build, not an earlier one. A recording of a version that no longer exists is worse than no recording.

---

## The recording

Full flow, no cuts, no narration track. Screen capture at presentation resolution.

Length should match the live demo — if the live run is 90 seconds, the recording is 90 seconds. A recording that runs at a different pace than your spoken script is unusable as a substitute.

Store it locally on the presenting laptop, not in cloud storage. Venue wifi is not a dependency you want in the fallback path.

## Reliability notes

Things that have broken demos before and are guarded against here.

**Corpus mismatch.** `index.bin` and `games.json` out of sync returns the *wrong games* with plausible scores — everything looks fine and is completely wrong. Guarded by a length assertion at boot that throws loudly. `pnpm corpus:verify` checks it explicitly.

**Clock-dependent scoring.** Release risk takes `today` as a parameter rather than reading the clock. A demo rehearsed at 11pm and presented at 10am would otherwise shift every week bucket.

**Stale snapshot.** Editing the concept after analysis shows a banner rather than silently mixing old and new numbers. If you edit something during a demo, the UI tells the audience it needs re-running instead of showing an incoherent mix.

**Empty calendar.** If the upcoming corpus is too thin, the climax screen looks broken. Checklist item requires ≥3 competing releases in the highlighted week; if that fails, the fix is more upcoming data, not a different demo week.

**Print preview left to last.** Charts clipping across page breaks is discovered at the worst possible time. Verify at feature freeze, not after.

## After the demo

```bash
git tag demo-presented
```

Tag it. Whatever happens next, the exact state that was shown is recoverable, and the repository history reads as a build that shipped rather than one that stopped.
